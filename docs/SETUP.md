# دليل التشغيل — رحلة الكتاب

الدليل ده مكتوب للخادم/المدرّس، ومش محتاج خبرة برمجة. امشي بالخطوات بالترتيب. كل حاجة هنا مجانية.

> ⚠️ الحدود المجانية لـ Supabase و Google Gemini و Cloudflare ممكن تتغير. راجعها وقت الإعداد.

---

## ٠. هتحتاج إيه

| الحاجة | منين |
|---|---|
| Node.js نسخة **22** أو أحدث | nodejs.org ← نسخة LTS |
| VS Code | code.visualstudio.com |
| حساب Supabase (قاعدة البيانات والسيرفر) | supabase.com |
| حساب Google (لمفتاح Gemini) | aistudio.google.com |
| حساب Cloudflare (لنشر الموقع) | dash.cloudflare.com |
| حساب GitHub (لرفع الكود) | github.com |

---

## ١. إنشاء مشروع Supabase

1. ادخل supabase.com ← **New project**.
2. اكتب اسم المشروع (مثلًا `rehlet-alketab`)، واختار كلمة سر قوية لقاعدة البيانات واحفظها.
3. **Region:** اختار أقرب منطقة لمصر (مثلًا Frankfurt).
4. استنى لحد ما المشروع يجهز (دقيقتين تقريبًا).
5. من **Project Settings ← General** انسخ **Project ID** (اسمه كمان Reference ID). هنحتاجه بعدين.

> ملاحظة: المشروعات المجانية **بتقف لوحدها** لو مفيش استخدام لفترة. لو حصل كده، ادخل لوحة Supabase واضغط **Restore**.

---

## ٢. تجهيز قاعدة البيانات

1. في لوحة Supabase افتح **SQL Editor ← New query**.
2. افتح الملفات دي من مجلد المشروع **بالترتيب**. انسخ محتوى كل ملف، والصقه، واضغط **Run**:
   - `supabase/migrations/20261118000001_init.sql`
   - `supabase/migrations/20261118000002_flexible_quizzes_per_day.sql`
   - `supabase/migrations/20261118000003_rate_limit_fn.sql`
3. للتأكد، شغّل `supabase/tests/m1_verify.sql`. كل الصفوف لازم يبقى فيها `rls_on = true` و `anon_select = false` و `policies = 0`.

> ❌ **متشغّلش** `supabase/seed.sql` على المشروع الحقيقي. ده بيانات تجربة بس.

---

## ٣. رفع السيرفر (Edge Function)

افتح مجلد المشروع في VS Code، وبعدين افتح **Terminal ← New Terminal** واكتب:

```bash
npx supabase login
npx supabase link --project-ref <Project-ID بتاعك>
```

بعد كده من لوحة **Run and Debug** اختار **☁️ Deploy Edge Function to Supabase** واضغط `Ctrl+F5`.
(أو اكتب في الـ Terminal: `npx supabase functions deploy api --no-verify-jwt`)

عنوان السيرفر بتاعك هيبقى بالشكل ده:
```
https://<Project-ID>.supabase.co/functions/v1/api
```

---

## ٤. ضبط الأسرار (Secrets)

في الـ Terminal:

```bash
npx supabase secrets set ADMIN_PASSWORD="اكتب-كلمة-سر-الخادم-هنا"
npx supabase secrets set ALLOWED_ORIGIN="http://localhost:5173"
```

- **ADMIN_PASSWORD:** كلمة السر اللي هتدخل بيها صفحة `/admin`. خليها طويلة ومتقولهاش لحد.
- **ALLOWED_ORIGIN:** عنوان الموقع اللي مسموح له يكلّم السيرفر. دلوقتي حطينا العنوان المحلي للتجربة، وفي الخطوة ٧ هنضيف عنوان الموقع الحقيقي.

(تقدر تعمل نفس الحاجة من لوحة Supabase: **Edge Functions ← Secrets**.)

> 🔒 مفتاح **service_role** بيتحط تلقائي على السيرفر. **متكتبهوش أبدًا** في أي ملف ولا تبعته لحد.

---

## ٥. مفتاح الذكاء الاصطناعي (Gemini)

1. ادخل aistudio.google.com ← **Get API key ← Create API key**.
2. انسخ المفتاح.
3. **متحطوش في الكود.** هتلصقه من صفحة الإعدادات في الموقع (الخطوة ٨).

> ملاحظات مهمة:
> - الحد المجاني محدود في اليوم والدقيقة. لو خلص، تصحيح المقالي هيستنى (معلّق)، وتقدر تصححه بنفسك أو تدوس "إعادة تصحيح المعلّق" بعد ما الحد يتجدد.
> - شروط استخدام البيانات في الخطة المجانية ممكن تسمح لجوجل تستخدم المحتوى. **متكتبش أسماء المخدومين** في الملاحظات أو نص الأصحاح. البرنامج نفسه مش بيبعت أسماء أبدًا.

---

## ٦. تشغيل الموقع على جهازك (للتجربة)

1. في مجلد `web` اعمل ملف اسمه `.env`، واكتب فيه سطر واحد:
   ```
   VITE_API_URL=https://<Project-ID>.supabase.co/functions/v1/api
   ```
2. في VS Code افتح **Run and Debug**:
   - **أول مرة بس:** اختار **📦 Install web packages** ← `Ctrl+F5`.
   - اختار **🌐 Web: dev server** ← `Ctrl+F5`. هيظهر لوجو "رحلة الكتاب" في الـ Terminal، والمتصفح هيفتح لوحده.
3. علشان تتأكد إن كل حاجة تمام: اختار **✅ Run all checks** ← `Ctrl+F5`. لازم تشوف **All green ✔** في الآخر.

---

## ٧. نشر الموقع على الإنترنت (Cloudflare Pages)

1. ارفع المشروع على GitHub (مستودع Private عادي).
2. في Cloudflare: **Workers & Pages ← Create ← Pages ← Connect to Git**، واختار المستودع.
3. الإعدادات:
   - **Root directory:** `web`
   - **Build command:** `npm run build`
   - **Build output directory:** `dist`
   - **Environment variables:**
     - `VITE_API_URL` = عنوان السيرفر من الخطوة ٣
     - `NODE_VERSION` = `22`
4. **Save and Deploy**. هتاخد عنوان زي `https://rehlet-alketab.pages.dev`.
5. ارجع للـ Terminal وحدّث ALLOWED_ORIGIN بالعنوانين (مفصولين بفاصلة):
   ```bash
   npx supabase secrets set ALLOWED_ORIGIN="https://rehlet-alketab.pages.dev,http://localhost:5173"
   ```

> Netlify شغال بنفس الطريقة (Base directory = `web`، Publish = `web/dist`). ملف `_redirects` موجود علشان صفحة `/admin` تفتح صح.

---

## ٨. أول دخول للخادم

1. افتح `https://<موقعك>/admin` وادخل بكلمة السر من الخطوة ٤.
2. **الإعدادات:** الصق مفتاح Gemini ← **حفظ** ← **اختبار الاتصال**. المفروض تظهر "الاتصال شغال ✓".
3. **المخدومين:** اكتب سطر لكل مخدوم:
   ```
   mina، مينا سامي
   مريم
   ```
   ← **إضافة**.
4. ابعت لكل مخدوم **اسم المستخدم** بتاعه بس. أول ما يدخل هيختار كلمة السر بنفسه.

> لو حد نسي كلمة السر: **المخدومين ← كلمة سر جديدة**، وهو هيختار واحدة جديدة أول ما يدخل.
> في الرئيسية تقدر تشوف مين فعّل حسابه. لو لقيت حساب متفعل وصاحبه لسه ما دخلش، اعمله "كلمة سر جديدة".

---

## ٩. الروتين اليومي (٥ دقايق)

1. **الاختبارات ← + اختبار جديد**.
2. اختار التاريخ والأصحاح (وميعاد الفتح لو عايز، مثلًا ٧:٠٠ م).
3. **توليد بالذكاء الاصطناعي:** الصق نص الأصحاح (أدق بكتير)، واختار عدد الأسئلة، ودوس **ولّد الأسئلة**.
4. **راجع كل سؤال وصححه.** الذكاء الاصطناعي ممكن يغلط.
5. لو فيه سؤال مقالي، اختار طريقة تصحيحه: **ذكاء اصطناعي** أو **يدوي**.
6. **نشر**. المخدومين هيشوفوه في معاده.
7. بعدين من **النتائج:** راجع الإجابات المقالية المعلّقة وصحّحها بزرار **صح / غلط**.

**تكليف مخدوم يكتب الأسئلة:** من **التكليفات** اختار المخدوم والأصحاح واليوم. لما يبعتها، دوس **راجع وحوّل لاختبار**، وراجع الأسئلة، وانشر. المخدوم اللي كتب الأسئلة مش هيمتحن الاختبار ده، والأيام المتتالية بتاعته مش هتتقطع.

**آخر السفر:** من الرئيسية فعّل **الترتيب ظاهر للمخدومين**.

## ١٠. لو حصلت مشكلة

| الرسالة | الحل |
|---|---|
| "الموقع مش متوصّل بالسيرفر" | `VITE_API_URL` ناقص. راجع الخطوة ٦ أو ٧. |
| "مفيش اتصال…" أو الصفحة مش بتحمّل | ممكن مشروع Supabase يكون واقف. ادخل اللوحة واعمل Restore. |
| "الموقع ده مش مسموح له" | ضيف عنوان موقعك في `ALLOWED_ORIGIN` (الخطوة ٧-٥). |
| "كلمة سر الخادم مش متظبطة" | `ADMIN_PASSWORD` مش متحطوطة (الخطوة ٤). |
| "وصلنا للحد المجاني" | استنى شوية أو لبكرة. الإجابات المقالية هتفضل معلّقة لحد ما تصححها. |
| "اسم الموديل مش متاح" | الإعدادات ← سيب اسم الموديل فاضي أو اكتب اسم موديل متاح. |
| "مفتاح الذكاء الاصطناعي مرفوض" | اعمل مفتاح جديد من AI Studio والصقه في الإعدادات. |

---

## ١١. الأمان باختصار

- **متشاركش** كلمة سر الخادم، ولا مفتاح service_role، ولا مفتاح Gemini.
- الملف `.env` **مش بيترفع** على GitHub (موجود في `.gitignore`).
- المخدومين **مش بيقدروا** يستخدموا الذكاء الاصطناعي خالص، ولا يشوفوا الإجابات قبل ما يسلّموا.
